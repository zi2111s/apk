# 屏幕脉搏 · ScreenPulse

Android 屏幕使用时间观察应用。使用 Android 公开的 `UsageStatsManager` 接口读取设备事件，不需要 Root。

**[手机直接下载最新版已签名 APK](https://raw.githubusercontent.com/zi2111s/apk/main/ScreenPulse-debug.apk)**

## 最新修正：2026-10-22

此前 v1.2.3 使用“前台事件累计”和“Android 日汇总”中**较大值**，这是错误的。实机同一时刻 vivo 官方显示 5小时47分，应用却显示 6小时23分；QQ、微信与小红书的单应用时长也明显错位。

本版纠正统计定义与数据来源（而不是盲目增加或减少分钟数）：

1. 今日主要指标使用**可观测屏幕交互区间**（如果 Android 真的返回可用的屏幕事件）；否则明示使用可观察前台事件累计，并提示可能漏报。界面标记真实数据来源。
2. 应用排行榜和24小时图**只来自同一个前台事件时间线**，不再把日汇总结果塞到部分应用里。
3. Android 日汇总独立展示在“为什么与系统不同”卡片中，**只作为诊断，不与事件混合或择大**。这样不再出现“事件图是一套时间、APP 排名来自另一套时间”的误导。
4. 昨天与近7日平均值使用与今天同一来源；缺少足够可观测历史事件就显示 **—**，不把不同来源的历史天数混算成十几小时。
5. 修复缺失 SCREEN_INTERACTIVE 启动事件时，首次活动恢复无法开启屏幕时长计数的问题。
6. 已通过本地 Kotlin 回归测试，覆盖活动切换、锁屏、整点分段、应用排行累计、交互时长区别等场景。

**必须说明：vivo 系统“健康使用设备”的官方统计可能来自厂商私有组件。普通第三方 App 无法保证凭 Android 公共 API 得到一模一样的数值。** 本版解决的是能验证的代码混算错误，不能承诺完全复刻系统数字。三个数据源现在并列展示，方便你直接对照。

## 升级方式

仓库 GitHub Actions 使用永久的私有签名 Secrets 构建 release APK、验证证书、自动增加 versionCode、更新根目录 `ScreenPulse-debug.apk` 和 [version.json](./version.json)。从 v1.2.2 及之后的同一签名版本，可直接覆盖安装而无需卸载。

[查看构建记录](https://github.com/zi2111s/apk/actions/workflows/build-apk.yml)

## 数据权限

使用记录本机查询和展示，不上传到服务器。只有在用户主动点击“检查软件更新”时联网读取公开版本文件。
